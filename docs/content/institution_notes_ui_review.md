## 推荐位置

放在详情面板的基本字段之后、来源父链与直属下级之前：

```text
历史单位记录
宣化府

有效时期       1644—1911
历史单位类型   府
历史单位类别   府州厅
来源所记上级   直隶省

清末的府
府通常处在省与所属州县之间……

来源记录中的上级关系
……

当前年直属下级
……
```

这样知识解释紧邻“历史单位类型”，但不打断实体的基本识别信息。

## 去重规则

详情面板最多显示一条：

1. 优先显示精确 raw type 对应的 `UNIT_TYPE` 条目。
2. `ERA_OVERVIEW` 不与类型条目同时显示，避免每个点重复同一段清末总览。
3. 若没有精确类型条目，则本批次不显示小识；不使用名称、坐标、父链或近似类型补配。
4. 1901—1911 之外不显示本批清末小识。

第一批不会匹配 `直隶厅`，因为 frozen raw type 中的 `厅`条目不应自动扩展到另一个明确 raw type。

## 视觉层级

- 标题使用“制度小识”，低于地点名称，高于正文。
- 小识标题如“清末的府”只出现一次。
- 正文常规字重，不用警告色，不做可展开大面板。
- 不在 User Mode 显示论文书目、来源 ID、审核状态或开发者 caveat。
- Developer Mode 可显示 note ID、命中 raw type、年份范围与 verified source IDs。

## 交互与失败边界

- 小识是只读信息，不增加按钮、弹窗或新 overlay。
- 候选缺失、JSON 异常或无匹配时，详情面板照常工作，只是不显示小识。
- 单条小识异常不得触发详情卡或整个 App 白屏。
- 切换年份或历史点时，按当前记录重新精确匹配。
